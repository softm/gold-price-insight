# 금시그널 AdFit 적용 계획

작성일: 2026-10-22 (한국시간)

## 1. 목표와 광고 구성

돌봄한눈의 하단 접기·펼치기 방식을 참고한다. 금시그널은 시세·차트·시나리오·목표가를 한 화면에서 연속 확인하는 대시보드이므로, 이번에는 **동시에 최대 한 개의 하단 광고**를 운영한다.

| 지면 | 이번 적용 | 크기와 동작 | 이유 |
|---|---|---|---|
| 하단 접기·펼치기 | 적용 | 모바일 320×100 / 데스크톱 728×90 중 한 개 | 본문을 읽는 동안 사용자가 표시 영역을 조절 |
| 본문 중간 배너 | 제외 | 추가 광고를 만들지 않음 | 짧은 대시보드의 차트·입력 흐름 유지 |
| 최초 진입 팝업 | 제외 | 웹 배너를 모달로 전용하지 않음 | 시세 확인을 방해하지 않고 Web 배너 배치 기준 유지 |

## 2. 매체 및 광고단위

2026-10-22 작업 중 관리 화면에서 확인한 상태다. 심사 결과는 이후 바뀔 수 있다.

| 항목 | 값 | 확인 상태 |
|---|---|---|
| 운영 URL | [goldsignal.designboard.net](https://goldsignal.designboard.net/) | 배포 대상 |
| AdFit 매체 | `ND9` / `goldsignal.designboard.net` | 매체 심사 대기 |
| 모바일 하단 | `DAN-4P5RJYzkhG0yWAns` / 320×100 | 기존 광고단위 승인 확인 |
| 데스크톱 하단 | `DAN-2vKaNDNMJpBLhNxx` / 728×90 | `금시그널_하단_PC_728x90` 신규 발급 확인 |

광고단위의 승인 표시를 매체 심사 승인으로 해석하지 않는다. 돌봄한눈의 ID를 복사하지 않고 금시그널 전용 실제 발급 ID를 사용한다. **모바일·PC 모두 소재 새로고침 및 대체광고 미설정**을 관리 화면에서 확인했다.

## 3. 화면과 동작 기준

| 상황 | 동작 기준 |
|---|---|
| 최초 표시 | 현재 폭에 맞는 단위 하나만 선택. 광고와 본문을 분리한 하단 영역 확보 |
| 본문·하단 내비게이션 | 광고 높이와 안전영역만큼 실제 가용 공간을 확보하여 마지막 콘텐츠와 내비게이션을 가리지 않음 |
| 제어 버튼 | 광고 소재 바깥의 별도 제어줄에 광고 표시와 접기·펼치기 제공. 광고 클릭 영역과 충분한 간격 확보 |
| 접기 | 사용자가 누르면 즉시 접고 선택을 `sessionStorage`에 기록 |
| 접힌 채 재방문 | 현재 탭 세션의 선택 복원. 사용자가 펼치기 전 최초 SDK·광고 요청을 시작하지 않음 |
| 다시 펼치기 | 이미 로드한 슬롯 재사용. 접기·재펼치기를 새 광고 요청의 계기로 삼지 않음 |
| 시세·시나리오 갱신 | 시장 파일 갱신, 슬라이더 조작, 목표가 저장, 탭 이동으로 광고를 재생성하지 않음 |
| 화면 폭 변경 | 같은 페이지에서 SDK나 광고단위를 중복 생성하지 않음. 이미 선택한 크기가 들어가지 않으면 광고 영역을 숨김 |
| 실패·광고 없음·로더 차단 | 광고 슬롯을 숨기고 본문에 공간 반환. 빈 대형 광고 상자나 재시도 반복을 남기지 않음 |
| 핵심 입력 중 | 목표가 등 입력에 포커스가 있는 동안 하단 광고 영역을 임시 숨김. 입력 종료 후 표시 상태를 복원하되 재요청하지 않음 |
| 백그라운드·오프라인·낮은 화면 높이 | 하단 영역을 임시 숨기고 사용자의 접힘 선호는 보존 |
| 호출 가능한 주소 | HTTPS `goldsignal.designboard.net`에서만 요청. 로컬·미러·오프라인 번들은 제외 |

접기 기능은 화면 표시 선택이다. 광고 추적 동의나 맞춤형 광고 설정을 대체하지 않는다. 앱에서 재요청하지 않는 것과 광고 SDK 내부 통신이 전혀 없다는 것은 다르므로 실제 동작을 확인한다.

## 4. SDK 연동 및 정책 근거

공식 `ins.kakao_ad_area`와 HTTPS `ba.min.js`를 사용하고 페이지에서 로더를 한 번만 설치한다. 발급된 ID·너비·높이를 그대로 사용한다. **SDK 준비와 광고 등록을 분리**하여 `kakaoAdFit.cmd`의 준비 콜백 뒤에 슬롯을 생성하고 `adfit.render(ins)`를 한 번 호출한다. 접기·재펼치기와 화면 변경에서는 같은 슬롯을 재사용한다.

`render`, `destroy`, `data-ad-onload` 지원은 2026-10-22 검사한 공식 배포 SDK 4.41.4의 실제 코드에서 확인했다. 이 API들이 공개 README에 모두 문서화된 것은 아니므로 제공 여부를 확인하고 사용할 수 없으면 광고 영역을 반환한다. 공식 문서의 `data-ad-onfail`과 실제 SDK의 `data-ad-onload`로 결과를 처리하며, 광고를 표시할 수 있는 구간을 기준으로 30초 타임아웃을 적용한다. SDK 자체는 수정하지 않는다. 서비스 워커는 제3자 광고 요청을 캐시하거나 앱 문서로 대체하지 않는다.

[운영정책](https://adfit.kakao.com/web/html/use_kakao.html)은 콘텐츠 가림, 광고 내부 닫기 버튼, 오클릭을 유발하는 인접 배치 및 과도한 반복 노출을 제한한다. 하단 접기형을 명시적으로 승인한 조항은 없으므로, 본문과 분리한 공간 확보는 해당 조건을 충족하기 위한 설계 판단이다. 최종 게재 적합성은 매체 심사와 구분한다.

## 5. Android 및 개인정보

기존 Android WebView의 쿠키·제3자 쿠키 차단 설정은 유지한다. 네이티브 SDK를 새로 추가하거나 Android 광고 식별자를 취득하는 변경은 이번 범위에 포함하지 않는다. 공개 WebView 참고 가이드가 있다는 사실만으로 현재 WebView의 모든 광고 기능이 검증된 것으로 보고하지 않는다.

웹 화면 변경은 최신 화면을 로드하는 Android 앱에도 영향을 준다. SDK 정적 검사에서 `sdkid`·`dk`, 페이지 주소, OS·브라우저·화면·네트워크 정보 및 조건부 배터리·오류 정보의 전송 경로를 확인했다. 쿠키 차단만으로 생성 식별값의 전송이 없어지지는 않는다. 공개 개인정보처리방침은 목표가 로컬 저장과 이 광고 처리를 구분한다.

[Google Play 데이터 보안 근거](../store/data-safety.md)와 [콘솔 답변표](../store/play-console-answers.md)에 실제 콘솔 작업을 남긴다. 광고 포함 여부와 데이터 수집은 **예**를 기준으로 정정하며, 공유·목적·필수성·서버 보유기간 등은 공급사 근거와 실제 환경을 추가 확인한다. 코드의 요청 생성 확인을 실제 서버 보유기간 확인이나 콘솔 제출 완료로 표시하지 않는다.

## 6. QA 및 완료 판정

아래는 검증해야 할 항목이다. 체크 표시가 없는 항목을 검증 완료로 간주하지 않는다. 실제 광고 클릭이나 반복 노출을 QA 수단으로 사용하지 않는다.

- [ ] 모바일 320/360/390px 및 데스크톱에서 한 개 슬롯만 사용
- [ ] 광고와 접기 버튼이 겹치지 않고 마지막 본문·하단 메뉴에 접근 가능
- [ ] 접기 → 재펼치기에서 로더·광고 DOM이 중복되지 않음
- [ ] 같은 탭 새로고침에서 접힘 유지, 접힌 최초 상태에서는 광고 요청 없음
- [ ] 시세·시나리오·목표가 갱신으로 광고 요청이 증가하지 않음
- [ ] 좁아진 화면에 광고가 잘리거나 수평 스크롤을 만들지 않음
- [ ] 실패 콜백·SDK 차단·NO-AD 시 슬롯 숨김과 공간 반환
- [ ] 핵심 입력 포커스 중 광고 영역 임시 숨김 및 입력 후 복원
- [ ] 키보드 조작, 버튼 이름·상태, 모바일 안전영역 확인
- [ ] 오프라인·로컬 미리보기에서 운영 광고 요청 방지 확인
- [ ] 운영 배포의 실제 단위 ID·SDK 요청과 관리 화면의 심사 상태를 각각 확인
- [ ] 개인정보처리방침 배포 확인
- [ ] Android WebView 실제 광고 처리 및 Play Console 변경사항 별도 확인

| 완료 단계 | 증거 |
|---|---|
| 구현 완료 | 하단 UI, 실제 ID 설정, 실패 처리, 회귀 확인 |
| 배포 완료 | 운영 URL에서 변경 파일·화면 확인 |
| 매체 승인 | AdFit 관리 화면의 매체 심사 결과 |
| 광고 송출 | 승인 여부와 별도로 실제 광고 수신 상태 확인 |
| 스토어 반영 | Play Console 광고·데이터 보안 저장 및 제출 상태 |
